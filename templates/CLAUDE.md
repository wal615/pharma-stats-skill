## 这是什么项目
- 研究编号：[如 ABC-123]
- 阶段 / 适应症：[如 III 期 / 2 型糖尿病]

## 目录结构
- `sdtm/`    SDTM 数据集（只读，统计不修改）
- `adam/`    ADaM 数据集程序，一 dataset 一程序
- `tlf/`     TLF 程序，一张表 / 一张图一程序
- `macros/`  公共宏（关键衍生逻辑只在这里写一次）
- `specs/`   定稿 spec（ADaM spec、TLF shell）—— 只读，禁止修改
- `docs/`    `STUDY_MAP.md` 全项目索引
- `output/`  程序输出（xpt / rtf / pdf），不进 git，不要直接改

## 数据流
```
SDTM →（adam/ 程序）→ ADaM →（tlf/ 程序）→ TLF
```
改上游必须重跑下游，并在回复里明确说明影响了哪些下游程序。

## 编辑流程（每次必做）
1. 先 Read 要改文件的当前内容——即使本会话已经读过它。
2. 再做最小范围的修改，只改被要求的部分。
原因：我经常在 RStudio 里手动改代码，你记忆中的版本可能是旧的；凭旧版本改写会覆盖我的手动修改。

## 执行规则（默认我来跑）
- 默认不要自己执行 R/SAS 代码：写好代码后告诉我跑哪个文件、怎么跑（Source 整个文件 / 选中运行 / 命令行），然后等我把输出贴回来。
- 只有当我明确说“你来跑”时，你才可以执行。
- 给我的每段代码必须是可独立运行的：文件开头自己加载 library 和数据，不要依赖你那边会话里的中间变量；如果某段代码必须依赖前面的步骤，明确写出前置步骤。

## 铁律（违反任何一条都要先停下来问我）
1. `specs/` 下任何文件不经我明确批准不得修改；spec 是唯一的 truth source，有歧义先问我，不要自己发挥。
2. 一次只做一件事：一个 session 只改一个 dataset 或一张表，任务切换就开新 session。
3. 只读元数据（define.xml、spec、数据字典），不要把原始受试者数据贴进对话。
4. 所有代码改动必须经人复核后才能用于正式分析（GxP 要求）。
5. 程序跑完必须检查 log：零 ERROR；有 WARNING 必须逐条解释。
6. 删文件、覆盖 `output/` 下的定稿结果前必须先问我。
7. 不确定的地方先列出你的理解和依据，等我确认再动手，不要猜。
